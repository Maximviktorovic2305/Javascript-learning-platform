# Программа JSlab

Все направления доступны бесплатно. У каждой главы три независимых этапа: изучение теории, решение задачи и тест. Вопросы проверяют понятия и применение опубликованного контракта задания. После неудачного теста доступен разбор; скрытые тестовые случаи практики не публикуются.

| Курс | Глав | Содержание |
| --- | ---: | --- |
| JavaScript | 22 | Выполнение языка и оболочка solve/return, значения, числа, строки, ветвления, циклы, функции, массивы, объекты, коллекции, замыкания, классы, ошибки, асинхронность, модули, event loop, DOM, события, Fetch, Storage, даты/RegExp, тестирование |
| TypeScript | 12 | Типы, union и narrowing, интерфейсы, функции, tuples, generics, keyof, utility types, mapped/conditional types, unknown и runtime-проверка, классы, модули и настройки компилятора |
| Express 5 | 12 | HTTP, routing, middleware, Router, query, валидация, CRUD, ошибки, async, архитектура слоёв, сессии и права, интеграционные тесты |
| NestJS 11 | 14 | CLI и запуск, модули, DI, контроллеры, DTO, pipes, guards, декораторы и метаданные, interceptors/RxJS, filters, конфигурация, хранение и транзакции, тесты, lifecycle |

Теория включает последовательное объяснение механизма, несколько примеров кода, типичные ошибки и подготовку к задаче. Оглавление доступно непосредственно в уроке. Источники хранятся в исходной карте программы: MDN, TypeScript, Express, Nest и learn.javascript.ru. Материал написан на русском для этой платформы, без переноса Python-уроков.

## Исходники и генерация

`scripts/curriculum/outline.mjs` задаёт порядок, модули и источники. `theory/{id}.md` содержит текст главы в ограниченном Markdown: заголовки второго уровня, абзацы, списки и fenced code. Парсер создаёт структурированные блоки; frontend выводит текст через Vue interpolation и не исполняет HTML из учебного материала.

`base-lessons.json` сохраняет идентификаторы прежних тем и их задания. `practice-*.mjs` добавляют новые задания и явно уточняют существующие контракты. `assessments.mjs` объединяет их. Сборщик создаёт `backend/src/catalog/data/lessons.json`, который коммитится вместе с исходниками:

```sh
node scripts/build-curriculum.mjs
```

Сборка проверяет наличие всех глав, не менее шести разделов, 450 слов объяснений без кода и трёх примеров в каждой. `progression.mjs` дополнительно разбирает синтаксис примеров, эталонов и кода вопросов через TypeScript AST: условия, циклы, callbacks, массивы, async, модули и продвинутые типы не могут появиться раньше объясняющей главы. Это проверка известных зависимостей, а не автоматическая оценка всей педагогики. У каждой главы три концептуальных и два прикладных вопроса. `applied.mjs` содержит 120 самостоятельных примеров: вопрос показывает необходимый код, входные данные или точный HTTP-запрос и не требует вспоминать условие практики или неизвестную реализацию `solve`. Всего 300 вопросов и 214 случаев для 60 задач. `test-sandbox.mjs` проверяет в изолированных контейнерах 51 вычисляемый пример и 15 HTTP-примеров с настоящим Express/Supertest; вопросы о типах и конфигурации дополнительно проверяются при редактуре.

Первый урок отдельно объясняет минимальную оболочку функции и `return`; подробные формы функций и callbacks вводятся в главе о функциях. Первое упражнение возвращает готовую строку без ветвления, расчёт двух цен не требует `reduce`, а динамический импорт находится после `async/await`. Начальные главы TypeScript и Express ссылаются на завершение JavaScript; Nest — на TypeScript и Express. Стабильные ID уроков сохраняются при уточнении порядка. Серверные заготовки содержат только используемые импорты библиотек, без копирования эталонной логики.

Редактор практики использует CodeMirror для подсветки JavaScript/TypeScript и Prettier в отдельном браузерном Worker. Видимая панель Prettier позволяет выбрать 2/4/8 позиций отступа, пробелы или табуляцию, длину строки, кавычки, точки с запятой, размер шрифта и перенос длинных строк. Настройки сохраняются на устройстве; автоформатирование после вставки и выхода из редактора можно отключить. Перед запуском, по кнопке и Alt+Shift+F применяется выбранный стиль. Синтаксически незавершённый код сохраняется без изменений. Форматирование не исполняет введённую программу.

## Проверка изменений

Меняя правило, одновременно обновляйте теорию, условие, подсказку, эталон, граничные случаи и вопросы. Стабильные ID сохраняют связь с прогрессом пользователей. Публичный Catalog API исключает эталоны, скрытые случаи и правильные варианты ответов до сдачи теста.

```sh
docker build -t script-lab-sandbox:1 runner/sandbox
node scripts/test-sandbox.mjs
```

Сценарий передаёт эталоны в одноразовые контейнеры, а не исполняет их на хосте. Для TypeScript включена строгая проверка типов. DOM-задачи используют Linkedom, Express — настоящее приложение с Supertest, Nest — application context, HTTP и TestingModule по смыслу главы. Подключение к настоящей БД не требуется внутри сетево изолированного учебного runner; БД и транзакции итогового проекта проверяются отдельно.

Тема завершена только после серверного зачёта всех трёх этапов. Частичный успех и сохранённые неудачные попытки показывают «В процессе». Открытый сейчас этап также помечается как текущая работа. Получение XP идемпотентно: повторное прохождение обновляет знания, но не выдаёт повторную награду.
